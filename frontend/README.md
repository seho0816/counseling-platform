# 마음기록 프론트엔드

상담·복지기관용 상담기록 요약 및 비대면 상담 지원 시스템의 웹 화면이다. React 18 + TypeScript + Vite로 만들었고, 모든 화면이 Spring Boot 백엔드의 API와 연결되어 있다. 가상 데이터로 동작하는 화면은 없다.

## 실행(개발)

Node.js 18 이상, JDK 23이 필요하다.

**터미널 1 — Spring Boot** (`.env`는 GitHub에 올라가지 않으므로 팀에서 따로 전달받는다)

```bash
cd counseling-platform/backend
set -a
source ../.env
set +a
./gradlew bootRun
```

**터미널 2 — React**

```bash
cd counseling-platform/frontend
npm install        # 처음 한 번
npm run dev        # http://localhost:5173
```

프론트에서는 서버 주소를 직접 쓰지 않고 `/api/...`로만 요청한다. 개발 중에는 Vite 프록시(`vite.config.ts`)가 `/api`를 `localhost:8080`으로 전달한다. 설정을 바꾸면 Vite를 다시 시작해야 한다.

## 배포(Vercel + Render)

- `vercel.json`이 `/api/*`를 Render의 백엔드(`https://counseling-backend.onrender.com`)로 전달하고, 그 밖의 주소는 `index.html`로 보낸다(새로고침해도 404가 나지 않게 하는 설정). 브라우저에는 한 도메인으로 보이므로 CORS와 로그인 쿠키(SameSite) 문제가 생기지 않는다. 백엔드 주소가 바뀌면 `vercel.json`의 `destination`만 고친다.
- 프론트엔드에는 API 키나 AI 서버 토큰이 없다. 환경 변수도 필요 없다.
- **Render 무료 서버는 한동안 쓰지 않으면 잠든다.** 처음 요청은 1분 가까이 걸릴 수 있어서, 화면은 요청마다 최대 75초까지 기다리고(챗봇은 30초), 로그인 화면은 서버가 깨어날 때까지 5초 간격으로 다시 확인하며 안내를 보여준다. AI 요약은 10초 넘게 걸리면 "오래 걸리고 있어요" 안내를 덧붙인다.

### 배포 후 점검 목록

| 순서 | 확인 | 기대 결과 |
| --- | --- | --- |

| 3 | 관리자 로그인, 개발자 도구 Network | `csrf` → `login` → `csrf` → `me` 모두 200, 쿠키 `JSESSIONID` 생성 |

| 9 | 관리자: 상담사 사용 중지 → 그 계정으로 로그인 | 로그인 실패 / 다시 사용 후 로그인 성공 |
| 10 | 관리자: 접근 로그 | 위 동작이 기록됨 |
| 11 | 챗봇: 메뉴 버튼, 질문지 3단계 → 이대로 접수하기 → 신청서 제출 | 서버 답변 표시, 신청서에 분야·고민·이전 상담 경험이 미리 채워짐 |
| 12 | 세션이 끝난 뒤(또는 다른 탭에서 로그아웃 후) 아무 화면에서 새로 불러오기 | 로그인 화면으로 이동 |
| 13 | 모바일 폭(약 375px)에서 로그인·사례·챗봇 | 가로 스크롤 없이 사용 가능 |
| 14 | 입력한 데이터 | 가상 데이터만 사용(실명·실제 연락처 금지) |

## 화면과 API 연결 현황

| 화면 | 주소 | API |
| --- | --- | --- |
| 서버 상태(로그인 화면) | `/login` | `GET /api/health` |
| 로그인·로그아웃·로그인 상태 | `/login` | `GET /api/auth/csrf`, `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout` |
| 비회원 상담 신청(공개) | `/apply` | `POST /api/intakes` (개인정보 동의 필수) |
| 비대면 안내 챗봇 | `/client/chatbot` | `POST /api/chatbot/message` (규격 기준 연결, 서버 구현 대기) |
| 사례 목록·상세 | `/counselor/cases`, `/admin/cases` | `GET /api/cases`, `GET /api/cases/{id}` |
| 사례 상태 변경 | 사례 상세 | `PATCH /api/cases/{id}/status` |
| 상담 회기 목록·작성·수정·상세(상담사) | `/counselor/cases/:id/sessions/…` | `GET·POST /api/cases/{id}/sessions`, `GET·PATCH …/{sessionId}` |
| AI 요약 생성·검토·수정·승인(상담사) | 회기 화면 | `POST …/summary/generate`, `GET …/summary`, `PUT …/summary/confirm` |
| 사례 등록·상담사 배정(관리자) | `/admin/cases/new`, 사례 상세 | `POST /api/admin/clients`, `POST /api/admin/cases`, `PATCH /api/admin/cases/{id}/assignment` |
| 상담 신청 목록·상세·사례 전환(관리자) | `/admin/intakes` | `GET /api/admin/intakes(/{id})`, `POST …/{id}/convert` |
| 상담사 계정 목록·등록·사용 중지/다시 사용(관리자) | `/admin/accounts` | `GET·POST /api/admin/counselors`, `PATCH /api/admin/counselors/{id}/status` (본문 `{"isActive":true|false}`) |
| 접근 로그(관리자) | `/admin/logs` | `GET /api/admin/logs` |

내담자 입장(로그인 화면의 "내담자" 탭)은 서버 로그인이 아니다. 별칭만 입력하면 챗봇 화면으로 들어가며, 브라우저 안에서만 유지된다(sessionStorage).

## 챗봇

서버가 규칙 기반 + AI 안내로 답하고, 화면은 그 응답을 보여주기만 한다. 상담·진단·치료는 제공하지 않고 기관 안내와 상담 신청만 돕는다.

| 서버 응답 | 화면 동작 |
| --- | --- |
| `reply` | 말풍선에 글자 그대로 표시(HTML·마크다운은 해석하지 않음) |
| `type: CRISIS` 또는 `action: SHOW_HELP` | 위기 안내 말풍선 + "109에 전화하기" 버튼. 입력한 글에 위기 표현이 있어도 **서버 응답을 기다린 뒤에** 보여준다(화면에서 미리 판단하지 않음) |
| `action: OPEN_INTAKE` | "초기 질문지 작성"과 "신청서로 바로 가기" 선택지 |
| `action: SHOW_MENU` 또는 `null` | 기본 메뉴(기관·프로그램 안내, 상담 신청 절차, 초기 질문지 작성, 신청서로 바로 가기) |
| 대기 중 | "답변을 준비하는 중이에요", 입력 잠금. 10초가 넘으면 "늦어지고 있어요" 안내 |
| 오류·시간 초과(30초)·형식 오류 | 고정 안내(긴급 연락처 119·112·109 포함)와 메뉴 |

- 메뉴 버튼은 서버에 질문 문장으로 보낸다. 문장은 `src/chatbot/script.ts`의 `MENU_QUESTIONS`에서 바꾼다.
- 초기 질문지는 3단계다: 분야(진로·학업 / 대인관계 / 우울·불안 / 기타), 고민(자유 입력, 건너뛰기 가능), 이전 상담 경험(있음 / 없음 / 답하지 않음). 고민 글은 위기 표현 확인을 위해 서버에도 보낸다.
- 질문지를 마치고 "이대로 접수하기"를 누르면 `/apply`로 이동한다. 분야·고민·이전 상담 경험이 미리 채워지고, 이름(별칭)과 개인정보 동의를 확인해 제출하면 `POST /api/intakes`로 저장된다. 서버는 고민 내용이 비면 거절하므로, 건너뛴 경우 신청서에서 쓰게 된다.
- 대화 중 위기 응답이 있었다면 신청서 위쪽에도 안전 안내를 보여준다(서버에 위기 표시를 저장하는 칸은 아직 없다).
- **챗봇 서버 API가 배포되기 전에는** 메뉴·글 입력이 모두 "안내를 불러오지 못했어요" 고정 안내로 끝난다. 질문지 → 신청서 흐름은 서버 챗봇 없이도 쓸 수 있다.

## 요약 화면에서 알아 둘 점

- AI 초안은 **승인 전에는 확정본으로 저장되지 않는다.** 상담사가 3항목(주요 고민·상담 개입 내용·향후 계획)을 확인·수정한 뒤 "승인"해야 한다. 승인은 상담사만 할 수 있다.
- AI가 기록에서 찾지 못한 항목(`기록에 없음`)은 빈 칸과 안내 문구로 보인다.
- 오류 안내: 400 기록 문제, 413 기록이 너무 김, 429 호출 한도, 502 AI 응답 오류, 503 AI 서비스 연결 실패(잠들어 있다면 1분쯤 걸릴 수 있음), 시간 초과.
- 서버에 요약의 임시 저장·직접 작성 API가 없어서, AI가 실패하면 "다시 시도"만 가능하다. 상담 기록은 이미 저장돼 있다.
- AI 요약이 만들어진 회기는 서버가 기록 수정을 막는다(409). 화면에서도 "기록 고치기"를 비활성으로 둔다.

## 오류 메시지와 시간 제한

서버가 오류 본문에 `message`를 담아 주지 않는 설정이면(스프링 기본값) 상태 코드별 한국어 안내만 보여준다. 본문에 `message`가 있으면 "서버 메시지: …"로 덧붙인다. 요청은 기본 75초가 넘으면 끊고 "응답이 너무 늦어요"를 안내한다. 401(세션 만료)이면 로그인 화면으로 이동한다.

## 로그인이 안 될 때

- "서버에 연결하지 못했어요"·"서버가 깨어나는 중" → 잠시 기다렸다가 새로고침. 개발 중이면 Spring Boot가 켜져 있는지(`http://localhost:8080/api/health`가 OK인지) 확인한다.
- "이메일 또는 비밀번호가 맞지 않아요" → 등록된 이메일(소문자)과 비밀번호인지 확인한다. 사용 중지한 상담사도 같은 안내가 나온다.
- 목록이 비어 있음 → 상담사 계정이면 본인에게 배정된 사례만 보인다. 관리자 계정으로 확인한다.

## 확인이 필요한 값

- 위기 안내 문구와 긴급 연락처(119·112·109)는 상담 전문가·기관 확인 후 확정한다. 위기 응답 본문은 서버가 주고, 화면의 고정 문구(`src/constants/crisis.ts`, 챗봇 오류 안내)는 서버와 같은 내용인지 맞춰야 한다.
- 챗봇 한 번에 보낼 수 있는 글자 수는 500자로 가정했다(`CHAT_MESSAGE_MAX`). 서버 제한이 정해지면 맞춘다.
- 개인정보 수집·이용 동의 문구(`ApplyPage.tsx`)는 초안이다. 실제 운영 전에 기관 확인이 필요하다.
- 상담 분야 목록(`src/constants/fields.ts`)은 초안이다.

## MVP 범위 밖

실시간 채팅, 음성 상담, AI 직접 상담, 내담자 로그인, 상담사 찾기·일정 예약은 이번 범위에 넣지 않았다. 화면에서도 제거했다.

## 다음 단계(서버 API가 생기면)

1. 요약 임시 저장·직접 작성 API → AI 실패 시 "직접 작성" 경로
2. 내담자 목록 API → 사례 등록에서 번호 입력 대신 선택
3. 위기 표시 저장 → 신청서·사례 목록에 표시
4. 사례 상태 변경 이력 → 사례 상세에 표시
5. 접근 로그 필터(사용자·동작·결과) → 로그 화면에 추가
