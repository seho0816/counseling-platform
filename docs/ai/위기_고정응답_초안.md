# 위기 대응 고정 응답 초안 (10번)

팀이 직접 확인·수정하는 초안이다. 담당 교수님 또는 상담 현장 경험자의 자문을 받은 뒤 확정한다.

## 1. 동작 방식 (가장 중요)

위기 표현의 감지는 AI가 아니라 **코드가 먼저** 한다.

1. 사용자가 챗봇에 글을 보낸다.
2. 코드가 아래 탐지 표현 목록과 비교한다. 이 단계에서는 AI를 호출하지 않는다.
3. 일치하면 AI를 부르지 않고 아래 고정 문구와 연락처를 그대로 보여 주고, 상담사 화면에 알림을 보낸다 (FR-SAF-01, FR-SAF-04).
4. 일치하지 않을 때만 AI 챗봇을 호출한다.

## 2. 고정 문구 초안

> 지금 많이 힘드신 것 같아요. 혼자 견디지 않으셔도 괜찮아요.
> 지금 바로 이야기할 수 있는 곳을 알려 드릴게요.
> - 기관 상담 연락처: 02-0000-0000 (가상 번호, 운영 시간 내 연결)
> - 긴급한 위험이 있다면 119 또는 112
> - 자살예방 상담전화 109 (24시간)
>
> 이 안내는 미리 정해진 문구이며, 기관 상담자에게 알림이 전달되었습니다.

- 기관 번호는 가상이다. 공공 연락처(119, 112, 109)는 **시연 전에 공식 안내에서 번호를 다시 확인**한다.
- 문구는 상대의 상황을 인정하고, 혼자가 아님을 알리고, 연락처를 안내하는 순서로 짧게 쓴다. 방법이나 상황을 자세히 묻지 않는다.

## 3. 탐지 표현 목록 (시작용, 팀과 자문으로 보완)

구체적인 방법을 나타내는 표현은 이 목록에 넣지 않는다. 일상 표현과 구분하는 것이 중요하다.

| 분류 | 예시 표현 | 비고 |
| --- | --- | --- |
| 죽음·사라짐에 대한 직접 표현 | 죽고 싶다, 살기 싫다, 사라지고 싶다 | 가장 기본 |
| 간접 표현 | 다 끝내고 싶다, 더는 못 버티겠다 | 일상 표현과 겹칠 수 있어 자문 필요 |
| 자해 표현 | 나를 해치고 싶다 | |
| 타인 위해 표현 | 누군가를 해치고 싶다 | 담당 교수님과 별도 논의 |

## 4. 테스트 케이스 (13주차 검증용)

| 구분 | 입력 예 | 기대 결과 |
| --- | --- | --- |
| 위기 표현 있음 | 목록의 표현 각 1건 이상 | 고정 문구 출력, AI 호출 안 함, 상담사 알림 |
| 비슷하지만 일상 표현 | "시험 때문에 죽을 맛이에요", "배고파 죽겠어요" | 고정 문구가 나오지 않고 일반 챗봇 응답 |
| 띄어쓰기·오타 | "죽고싶다", "죽 고 싶 다" | 고정 문구 출력 (공백 제거 후 비교) |
| 범위 밖 요청 | "약 먹어도 돼요?" | 고정 문구 아님, 상담자 연결 안내 |

## 5. 확인할 것

- [ ] 고정 문구를 담당 교수님 또는 상담 현장 경험자에게 보여 주고 수정 의견 받기
- [ ] 공공 연락처 번호를 공식 안내에서 확인
- [ ] 탐지 표현 목록 보완, "일상 표현" 오탐 사례 추가
- [ ] 코드에서 위기 확인이 AI 호출보다 먼저 일어나는지 백엔드 팀원과 확인
